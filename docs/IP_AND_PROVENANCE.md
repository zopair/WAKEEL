## 3. ما الذي يمكن أن يثبته GitHub؟

يمكن لسجل Git أن يساعد في إظهار:
- معرفات commits وبصمات SHA للمحتوى.
- تسلسل النسخ والتعديلات وتواريخها المسجلة.
- الفروع وطلبات المراجعة والمناقشات.
- إصدارات Releases/Tags إذا أنشئت لاحقاً.
- توقيعات commits أو tags إذا أضيفت بمفتاح موثوق.

لكن تواريخ Git يمكن أن تُضبط من المستخدم، وحساب GitHub قد لا يثبت وحده الهوية القانونية أو ملكية كل عنصر. لذلك يعد المستودع **قرينة توثيق رقمية مساعدة** لا شهادة ملكية نهائية ولا بديلاً عن إجراءات التسجيل والإيداع الرسمية.

## 4. ممارسات توثيق موصى بها

1. إبقاء المستودع عاماً إذا كان الإفصاح مقصوداً، أو خاصاً إذا كان هناك محتوى سري لم يُعتمد نشره.
2. عدم تعديل التاريخ بأثر رجعي أو إعادة كتابة السجل لإظهار أسبقية غير حقيقية.
3. الاحتفاظ بسجل commits وPull Requests وعدم حذف المناقشات الجوهرية.
4. إنشاء Release/Tag عند اعتماد كل نسخة رسمية، مع وصف النطاق والتاريخ وبصمة commit.
5. استخدام توقيعات commits/tags عند توفر مفاتيح موثوقة، وحفظ سجل إدارة المفاتيح.
6. الاحتفاظ بنسخة أرشيفية مستقلة من كل إصدار، وبصمات SHA-256 للملفات النهائية.
7. إضافة سجل للمساهمين ومصادر البيانات والمكونات الخارجية وتراخيصها.
8. مراجعة الحاجة إلى إيداع أو تسجيل رسمي لدى الجهة المصرية المختصة بالملكية الفكرية أو مستشار قانوني متخصص قبل الإفصاح العام أو التفاوض التجاري.
